\subsection{Probes and loss computation}
\label{sec:app_probes}

Each capability is measured on a fixed probe set of prompt and reference pairs, drawn once with a
fixed seed from held-out benchmark splits that are disjoint from all training and recovery sources
used in the paper. The primary benchmarks are MATH-500 \citep{hendrycks2021math,lightman2023verify}
for mathematical reasoning, MBPP \citep{austin2021program} for code generation, and 2WikiMultihopQA
\citep{ho2020constructing} for multi-hop question answering. For each capability we draw 128 probes
and split them by index parity into an estimation half, used only for gradient and Fisher
statistics, and a measurement half of 64 probes on which each reported loss is computed, so that
mechanism statistics and evaluations do not share sampling noise. All reported results use the
64-probe measurement half unless a 512-probe re-measurement is stated.

The secondary benchmarks of the measurement checks (Appendix~\ref{sec:app_measure}) are GSM8K
\citep{cobbe2021gsm8k}, HumanEval \citep{chen2021codex} and HotpotQA \citep{yang2018hotpotqa} on the
pruning panel, where no training is involved, and SVAMP \citep{patel2021svamp}, HumanEval and
TriviaQA \citep{joshi2017triviaqa} where distilled models are scored, chosen so that no benchmark
from which distillation traces were derived is used to score a distilled model; MuSiQue
\citep{trivedi2022musique} serves as a second multi-hop distribution. A sample-level audit found no
overlap between any measurement probe and any training pool. The models are Pythia
\citep{biderman2023pythia}, Gemma 3 \citep{gemma2025gemma3} and Qwen3 \citep{qwen2025qwen3}, adapted
with LoRA \citep{hu2022lora}; the size-and-stage panel follows the observational use of released
checkpoints \citep{ruan2024observational,polo2024tinybenchmarks}.

\subsection{Compression protocols}
\label{sec:app_compress}

The three operations are fixed by protocol. Pruning is global magnitude pruning, which removes the smallest weights across the attention and MLP projection matrices, leaving embeddings, output head, biases and norms untouched, to a target retained density $\dens$. The global threshold is estimated from a seeded sample of
absolute weights, which lets the same procedure scale to 30B-parameter models, and each density is
applied to the same dense reference weights, so the densities are nested, and each pruned set contains the previous one.

Per-channel quantization fake-quantizes the weights per output channel with symmetric
round-to-nearest at bit-width $\bits$: integers are clamped to $[-q_{\max},q_{\max}]$ with
$q_{\max}=2^{\bits-1}-1$, the per-channel scale is the maximum absolute weight of the channel divided by
$q_{\max}$, and activations stay in bfloat16. The dense weights are restored between bit-widths.
Because the clipping range is fixed, the step size from 4 to 5 bits shrinks by $7/15$ and the
squared step ratio between adjacent bit-widths is $(q_{\max}(\bits)/q_{\max}(\bits+1))^2$ and
not a constant $1/4$. A squared step ratio becomes a loss ratio only under assumptions about the
error distribution and the local response that we do not test, so the $4^{-\bits}$ shape is one
candidate among others and not a derived reference. Nominal storage ratios are computed from
bit-widths; no memory or latency was measured.

The grouped variant of the same quantizer (Section~\ref{sec:law_quant}) splits each row of a
weight matrix into contiguous groups of $g$ input weights, pads the last group with zeros, which do
not affect the group maximum, and applies the same symmetric round-to-nearest with
$q_{\max}=2^{b-1}-1$ per group; $g$ equal to the row width reproduces the per-channel quantizer
exactly. The configurations are $b\in\{3,4,5\}$ and $g\in\{64,128,256\}$, with nominal storage
computed from $b$ and $g$ under the same convention as the per-channel case, so budgets are
comparable across the two quantizers.

Distillation, the third operation, fine-tunes students on black-box teacher traces, a frontier API teacher
answering GSM8K, HotpotQA and CodeAlpaca prompts with 600 traces per domain, under the full-trace
recipe: LoRA adapters of rank 16 and scaling 32 on the query, key, value, output, gate, up and down
projections, AdamW at learning rate $10^{-4}$ unless stated, an effective batch of 16 sequences, and
a cosine schedule with 3\% warmup. The training mode and the trainable parameter count are recorded
in each run manifest. Token accounting distinguishes processed tokens, which count each input token seen including repetitions, unique pool tokens, and supervised completion tokens. The data pool of $U$
examples per domain is either the first $U$ rows of the trace file, the historical protocol, or a
random sample drawn with a pool-sampling seed independent of the training seed; pools are
identified by the sorted hashes of their samples and pairwise overlaps are reported. The historical
schedule spanned a fixed number of epochs, so its cosine horizon varied with pool size; the
controlled matrix of Section~\ref{sec:law_distill} uses a schedule defined on the same absolute
processed-token budget for each pool, and the two protocols are not mixed in any fit or any table of this paper.

\section{Measurement Validity}
\label{sec:app_measure}

The capability-specificity, same-capability agreement, independent multi-hop distribution, and
pre-specified eight-state scope checks are reported in Section S3 of the supplement.

The remaining two checks concern the link between loss and behavior and the choice of reference
condition. Loss-to-accuracy links were fit on
GSM8K accuracy, MBPP pass@1, and TriviaQA exact match and token F1
across seven pruned models; all four outcomes are compatible with one
cross-family sigmoid in the loss, with no resolved family-specific
term. A lower QA loss does not by itself imply better QA behavior: the
four pruned OLMo-3-32B cells whose QA loss lies below dense show no
increase in exact match. This audit covers pruning only and is not repeated for the other two methods, whose public panels
are smaller.

The reference condition was also varied. For a subset of models the
direct-answer and given-reasoning-answer conditional distributions were
measured in addition to the full-solution reference; they differ from
it for math and QA and coincide for code, where the reference is the
function body, so the numbers in this paper are specific to the
full-solution reference and should not be read as evidence of robustness to the reference format.

The loss is the conditional cross-entropy of the reference completion
given the prompt, summed over completion tokens and divided by the
number of completion tokens, as in Eq.~\ref{eq:taskloss}. Prompts and
references are tokenized with the tokenizer of each model and truncated to
1024 tokens; prompt tokens are masked out of the loss. All within-model
responses $\Delta L_c$ are differences in native-token nats
on identical token sequences. Because native-token units differ across
tokenizers, cross-family comparisons of absolute levels use per-byte
normalization or are reported separately, and no cross-tokenizer
quantity is treated as a common numerical scale. Negative responses are
retained as measured and are not clipped at zero.

study.

Under distillation, black-box traces from two API teachers, 600 per domain, train Gemma-3 students under a full-trace and an
answer-only recipe in a paired design. The answer-only recipe increases the math loss about twice as much as the full recipe, while QA improves by 0.6 to 1.4 nats under both; because the recipes differ in supervised tokens and update

The loss endpoint supports these comparisons within limits. The same
heterogeneity appears on independent secondary benchmarks for math and
QA, where the primary-benchmark response predicts the secondary one
better than the response of any other capability does, with intervals
excluding zero in most hold-out protocols; for code the
cross-capability predictor is as good or better

QA loss does not by itself mean better QA behavior: in the four pruned
OLMo-3-32B cells whose QA loss lies below dense, exact-match accuracy
does not rise. ``QA improves'' in this paper refers to the loss and to nothing else.


\subsection{Scale and family structure}
\label{sec:family}

Within a family, robustness is not monotonic in size, and this holds in two families
independently: Gemma-3 robustness peaks at 12B and 27B collapses far earlier, in line with the earlier
ability-space observation of a Qwen3 14B peak. A mid-scale robustness peak appears in both families, in the present grid and in the earlier one.
One candidate predictor of this structure was retired. The
top-concentration statistic $\kappa_c$ of the capability gradient tracked robustness within the
Qwen3 ladder and was pre-specified as a predictor. The full grid does not support it: across families the
ordering inverts, since OLMo, the most robust family, has the lowest concentration, and within
Gemma-3 the largest size violates the within-family trend, so the statistic was retired.
At matched scale, on the panel of models near 30B parameters, the
family coefficient dominates: $\Delta\Lc{\text{math}}$ at $\dens=0.7$
spans two orders of magnitude, from 0.02 nats on OLMo-3-32B through 0.17 on Muse-30B and 0.68 on Gemma-4-31B to 4.04 on Gemma-3-27B. OLMo-3-32B survives $70\%$ pruning with
$\le+0.63$ nats on each capability. Family identity is a first-order determinant of prunability on this panel; which training-data or recipe properties carry it was not measured and is left open on this panel.

\section{Relation Selection, Boundaries and Calibration}
\label{sec:app_forms}

This section records how each delivered relation was selected, where its boundary lies, which
capabilities it serves, and what structure the relations share.

\subsection{Selection and boundary of the delivered relations}
\label{sec:app_selbound}

The pruning relation was selected on the development panel. Fit on nine states at $d\in\{0.9,0.8,0.7,0.6\}$
and scored at the unseen 0.65 and 0.55, Eq.~\ref{eq:power} reduces the
strength-only error by a factor of two to three, and A2 matches it; refit on 17
states under a pre-specified leave-one-source-out rule, A2 and the power form tie within 0.02 nats, at 0.479 and 0.494, and the rule prefers the continuous form that vanishes at $d=1$; the coefficients are in Appendix~\ref{sec:app_coef}, and the exponent $\gamma_c$ is a fitted constant that has not been established as necessary.

Its boundary was then established. Evaluated as a pre-specified candidate on three new checkpoints, the power form reaches the math error of A2 with five parameters against twenty and does not beat the median curve on code or QA; on a 2.8B source the median curve is three to seven times better than either source form (Section~\ref{sec:general}). The compact form trades accuracy for compactness within a tested range; the median curve is the relation for new states, a rule fixed after these tests and reused without change in Section~\ref{sec:selection} for the selection rule and its confirmation.

For quantization, two parametric candidates were tested first, a
separable amplitude-times-shape form and a low-order surface in
$\log_2 q_{\max}$ and $\log_2 g$; the surface beat zero change at the
unseen $b=4$ and $g=128$ on the two-bit-level development set, but its quadratic term is unidentified there, with design rank 16 of 20, as Section S2 of the supplement shows. That earlier round contains the only test of a genuinely unseen bit width, and it is
reported here rather than in Table~\ref{tab:main-prediction-v2}. On the six development states at
bit width 4 with group sizes 64 and 256, fitted on 24 development configuration measurements per
capability, the pre-specified surface reaches 0.19, 0.21 and 0.44 nats on mathematics, code and question
answering, against 0.55, 0.73 and 0.54 for the development-selected median. The surface is not the
delivered relation, and the relation that is delivered can show no error of its own on these cells,
because they were added to the development grid of the round that selected it; the interpolation
variant scored on them in the earlier round uses different models and boundary rules and does not
stand in for it. Table~\ref{tab:main-prediction-v2} therefore carries only tasks on which the
delivered predictor has an independent error. In a confirmation round with all 54
unblinded cells as development set and 21 cells pre-specified at unseen
group sizes and on a new state, the interpolation won the pre-specified cells
for math and code and the median won the new state, so the delivered
rule was fixed after that round and is marked Retrospective in
Table~\ref{tab:main-prediction-v2} and in the tables of
Appendix~\ref{sec:app_results}. Table~\ref{tab:main-prediction-candidates} lists the pre-specified
candidate of each task beside the relation delivered after its test.

\subsection{Applicability across capabilities}
\label{sec:app_applic}

Where the initial-state inputs help is method- and range-specific:
they carry math and code at unseen pruning densities of seen sizes
and at unseen group sizes of seen states, add nothing on new
quantization states or in distillation beyond the reference anchor,
and over-predict the QA pruning response on each new checkpoint. What capability conditioning adds is measurable on the pre-specified
confirmation panels (Appendix~\ref{sec:app_shared}): per-capability
pruning curves beat a shared response curve with a signed
per-capability scale by 0.06 nats macro-averaged, largely through QA at 0.17 nats, whose aggregate curve is not proportional to the tested shared curve:
it changes sign across density, with a loss increase at $d=0.55$ and an improvement from 0.6 to 0.9, so no scale of that curve, including a negative one, represents it, and its direction also varies across sources. For math and
code a shared curve is as good or better, for grouped quantization the two are indistinguishable, and for distillation the
comparison is empty because the one-coefficient forms are
algebraically equivalent. Conditioning matters where the shape of the
response differs across capabilities.

\section{Mechanisms}
\label{sec:app_mech}

Four analyses develop the mechanism summary of Section~\ref{sec:resp_capabilities}: a pruning
law in the deleted capability mass, the sign of its first-order term, the geometry of the cliff, and
the logit-displacement account of the loss change, in that order.

\subsection{The pruning law}
\label{sec:law}

The mechanism form below fits the full pre-cliff grid.
With the measured alignment term subtracted, the curvature residual
follows a power law in the deleted capability mass $m_c(\dens)$:
\begin{equation}
\Delta\Lc{c}(\dens)\;=\;\underbrace{\gbar{c}^{\top}\dw_\dens}_{\text{measured}}
\;+\;C\,\big[\underbrace{m_c(\dens)}_{\text{measured}}\big]^{\eta},
\label{eq:fitlaw}
\end{equation}
where $\gbar{c}$ is the mean gradient of the capability loss at the dense weights, $\dw_\dens$ the
weight change from pruning to density $\dens$, $C$ a fitted amplitude and $\eta$ a fitted exponent,
with in-sample $R^2 = 0.82$--$0.996$ over 24 capability$\times$model fits. The form is tested on the held-out battery with a 1000-resample cell bootstrap: in \emph{leave-one-family-out} transfer the
shared-$\eta$ mechanism form attains MAE $2.17$ nats versus $10.3$
for per-capability raw sparsity and $8.2$ for the direct-damage baseline, with both intervals excluding zero, so the deleted-mass coordinate
transfers across families; it also beats the direct-damage baseline in fit-shallow/predict-deep and raw sparsity in leave-largest-model-out, while its edge over raw
sparsity within-model does not reach significance; without the first-order term QA is unfittable, and with it QA joins the law. Fig.~\ref{fig:explanation} shows the fitted reuse exponent and the accuracy of the displacement account against the size of the loss change. Two structural results follow. First, in the deleted-mass coordinate the exponent concentrates at
$\eta\in[1.2,2.2]$ across all families, versus $3.2$--$8.7$ in the
raw $(1-\dens)$ coordinate, which makes the form portable. Second, \emph{within a model, $\eta$ is shared across capabilities}: capability differences appear to be carried
by the two measured quantities, and the fitted structure is two
parameters per model. This mechanism form uses gradient
information of the dense model and is not a K0 predictor; it
is reported as an upper comparator for the reduced forms of the main
text and not as a bound on what the initial state can predict.

\subsection{The signed first-order term predicts, in both directions}
\label{sec:mech}

The alignment term $\gbar{c}^{\top}\dw$ is the family
coefficient that carries sign. Its sign predicts the presence or absence of the
capability-selective improvement in each case measured:
the QA term of Qwen3 is negative and QA improves under pruning, with a predicted $-0.83$ against a measured $-0.79$ at 4B and $\dens=0.7$; the QA term of Gemma is
positive and no improvement exists at any size; the term for OLMo-3-7B is positive, a mild degradation predicted and measured at $+0.015$ on code at $\dens=0.8$, while the term for OLMo-3-32B is negative, and
QA improvement under deep pruning appears. At the level of individual model$\times$capability$\times$density
cells in the mild regime, sign prediction accuracy is $67.6\%$ over 108 cells, above chance with a Wilson interval of 58 to 76 percent, and the family-level pattern of Qwen and OLMo-32B QA improvements, none for Gemma and an OLMo size flip was stated in advance. Beyond the mild regime, first- plus second-order
predictions fail by orders of magnitude at the cliff in each family:
the collapse is non-perturbative in loss space, consistent with the
two-regime structure of \eqref{eq:fitlaw}.

\subsection{The cliff is a geometric threshold crossing}
\label{sec:orderparam}

Measuring the capability geometry \emph{of the pruned models}
accounts for the location of the cliff on the three models tested. The capability-region mass retention, the fraction of the capability-exclusive top coordinates of the dense model still prominent after pruning, declines smoothly from the first densities with no cliff in geometry, while loss is still flat;
the behavioral cliff occurs where retention crosses a critical value.
The critical value is family-specific, near 0.04 to 0.10 for Gemma across sizes and capabilities and 0.13 to 0.23 for Qwen, but consistent
within a family across sizes and capabilities: the cliff boundary
$\dens_c^{*}(N_0,f)$, for size $N_0$ and family $f$, reduces to one critical-retention constant per
family, so the fitted cliff parameter of the two-regime
law becomes a measurable order parameter that varies smoothly within each family.

\subsection{The logit-displacement account of the compression loss change}
\label{sec:app_disp}

For a compressed model whose logits are displaced by $r$ from those of the reference, the change
in cross-entropy on a supervised token $y$ under the reference next-token distribution $\pi$ is
exactly
\begin{equation}
\Delta L \;=\; \big(\mathbb{E}_{\pi}[r]-r_y\big)\;+\;\tfrac12\,\mathrm{Var}_{\pi}(r)\;+\;O(\lVert r\rVert^3),
\label{eq:displacement}
\end{equation}
so the first-order term is the signed alignment of the displacement with the target and the
second-order term is coefficient-free. Evaluated on 339 cells across pruning, grouped quantization
and per-channel quantization on the development states, the truncation to second order reproduces
the measured loss change with a median relative error that depends on the loss-change magnitude and not on the
family or the knob (Table~\ref{tab:disp_boundary}): under 5\% wherever the loss change is below about
0.1 nats, and rising past 20\% by 0.25 nats. Grouped four-bit quantization with fine groups, at 0.06 nats, sits on the same error curve as per-channel four-bit quantization at 0.24 nats of damage.

Two readings of this account are excluded. Projecting the displacement onto the reference logits $\ell$
with a shift-invariant estimator, $\epsilon=-\mathrm{Cov}_{\pi}(r,\ell)/\mathrm{Var}_{\pi}(\ell)$, since the uncentred version moves by 85\% under a constant logit shift, the pure-shrinkage account
fails on magnitude: about three percent of the response lies in the shrinkage direction, and the
variance of the orthogonal residual carries the rest for math and code. That residual variance is
not shown to be random noise, and it is not a pre-compression predictor, because computing it needs
the compressed model. The account explains the loss change after the fact and enters no
relation as an input. Variance dominance is per capability: seventeen cells with negative loss
change are carried by the first-order term.

\section{Extended Discussion: Lessons, Guidance and Limits}
\label{sec:app_learned}

This section collects the discussion that the conclusion (Section~\ref{sec:learned}) summarises: the
responses and relations the study established, what was learned in trying to build reliable laws,
the guidance those lessons support, and the limits of the present relations.

The responses and relations come first. Compression changes capabilities unevenly and the unevenness is
structured: a capability-specific power form under pruning inside its density range, a
configuration-dependent quantization threshold that the measured grid predicts better than any
surface, and a distillation reuse cost that grows with reuse and student size and transfers across
QA distributions while the gain does not (Table~\ref{tab:main-prediction-v2}).

Building reliable laws taught four lessons. First, a rejected form is not a rejected class: the logarithmic reuse term failed its own flatness
implication, yet the fit-free second-difference test on two students did not reject additivity of
budget and reuse on the QA readout (Section~\ref{sec:why}). Second, an explanation is not a
predictor: the displacement account reproduces the loss change across three families and needs the
compressed model to compute. Third, source information transfers less than it fits: dense
pre-compression statistics improve a parametric family in four of nine pairs and lose to a
source-free configuration curve in nine of nine, with or without a shrunk source correction. Fourth, identifiability is a property of the design: the data that fitted a curvature exponent
contained no budget-by-reuse rectangle, so the one fit-free statistic that separates additive from
interacting structures was uncomputable until four trajectories were designed to land on one.

These lessons translate into guidance for design and choice. Inputs should be chosen by the transfer needed: the initial state
carries math and code at unseen densities and group sizes of seen states and over-predicts QA under
pruning on new checkpoints, so a calibrated configuration median is the safer default when the state
is new. The training protocol should be fixed before the distillation response is measured, since the learning rate moves it by
an order of magnitude. Data-reuse experiments should be designed so that a budget-by-reuse rectangle exists by
construction. Calibration should be judged per method against the accuracy it provides: one target measurement, the K1 budget as opposed to the K0 predictions, helped the quantization predictor, whereas for pruning a calibration point at the mildest density amplified noise, because an observation near zero loss change cannot estimate an amplitude stably; a calibration point must carry enough response signal, and the more expensive dense statistics did not earn their cost.

The limits are equally clear. The relations are conditional on the evaluated distributions and
implementations. No fitted joint structure for distillation beat a low-order response surface on
either pre-declared target, so a validated data-requirement relation is not delivered; the larger
student diverged from the smaller on math and code at readouts the design could not resolve.
Reopening measurement requires a new information source or a mechanism hypothesis; a further reuse
function fitted to the same data would not suffice.
